## 2. Phase 1: Identify (Zero-Trust Cryptographic Authentication)
Traditional static API keys present a massive risk if an autonomous agent is hijacked. We solved this by implementing a **Challenge-Response** system.

### Logic Implemented:
* **The Handshake (`src/identify/authentication.py`)**: When an agent attempts to act, it sends its public key. The `AuthenticationService` generates a one-time random `nonce` and a `session_id`.
* **The Proof (`src/utils/crypto.py`)**: The agent must use its private key to cryptographically sign the nonce. We implemented support for both `RSA` and `ECDSA` signature verification.
* **The Token**: Only if the signature is valid does the gateway issue a short-lived JSON Web Token (JWT).
* **Least-Privilege (`src/identify/capability_profiler.py`)**: Even if authenticated, agents are restricted to specific whitelisted capabilities (e.g., `agent-007` is allowed `read_file` but denied `delete_database`).

## 3. Phase 2: Track (Tamper-Proof Auditing)
To ensure complete forensic observability, we integrated HashiCorp Vault to create immutable logs.

### Logic Implemented:
* **Intent Logging (`src/track/models.py`)**: We mandated that every action payload must be accompanied by an `intent_summary` (an explanation of *why* the agent is doing this).
* **Vault Client (`src/track/vault_client.py`)**: Connected to Vault's Key-Value store to record the event, generating a secure `vault_receipt_id`.
* **Reasoning Middleware (`src/track/reasoning_capture.py`)**: Built an async middleware wrapper. It intercepts the request, forces the Vault log *before* execution, runs the tool, and logs the exit status afterward. If the database is compromised, the Vault logs remain untouched.

---

## 4. Phase 3: Contain (Ephemeral Sandboxing)
We completely isolated the execution of agent tools using dynamic Docker containers.

### Logic Implemented:
* **The Sandbox (`src/contain/container_provisioner.py`)**: We utilized the Docker Python SDK to dynamically spin up `python:3.11-slim` containers on the fly for every single action.
* **Aggressive Hardening**:
    * Enforced `cgroups` CPU and Memory limits to prevent DoS attacks.
    * Mounted the root filesystem as completely read-only.
    * Explicitly disabled network namespaces (`network_disabled=True`).
* **Kernel Protection (`config/seccomp_profile.json`)**: We wrote a strict Seccomp profile that defaults to `SCMP_ACT_ERRNO` (deny all) and only whitelists absolutely necessary Linux system calls.
* **Lifecycle Management**: Containers are aggressively terminated and deleted (`remove(force=True)`) immediately upon task completion or timeout (10 seconds), leaving no persisting state.

---

## 5. Phase 4: Decide (The Semantic Firewall)
We built a 3-Tier AI-native firewall to evaluate the context and intent of the agent's action.

### Logic Implemented:
* **Tier 1: Rule Filter (`src/decide/rule_filter.py`)**: A fast, deterministic gate. It instantly blocks hardcoded dangerous actions (`delete_database`) or restricted target paths (`/etc/shadow`, `.aws/credentials`) with a 1.0 risk score.
* **Tier 2: PII Redactor (`src/decide/pii_redactor.py`)**: A recursive regex parser that traverses the agent's payload and replaces sensitive data (Emails, Phone Numbers, SSNs, Credit Cards) with safe masks (e.g., `[REDACTED_EMAIL]`) to prevent data leakage.
* **Tier 3: Semantic Evaluator (`src/decide/semantic_evaluator.py`)**: Connects to a local Ollama LLM. It prompts the LLM with the agent's action, target, and intent, asking it to detect Prompt Injections or Goal Hijacking. It returns a risk score; anything `>= 0.7` is blocked.
* **Circuit Breaker (`src/decide/circuit_breaker.py`)**: A stateful defense mechanism. If an agent triggers 3 security blocks within 60 seconds, the circuit opens, completely severing the agent's access for a 120-second timeout period.
