Architecture

The ITCD pipeline

Every agent action flows through four phases in order: Identify, Track, Contain, Decide. Containment is established before the decision, so an action is only ever executed inside an already-isolated sandbox.

01 Identify

Pre-checks at the gateway. Any failure blocks the request before a container is ever created.

  • MCP Gateway: single authenticated entry point
  • IdentityRegistry: signed identity and live trust score
  • CapabilityProfiler: is this action authorized?
  • RogueDetector: anomaly and suspicious-pattern detection
  • KillSwitch and CircuitBreaker: global stop plus per-agent throttle
  • IntentCapsule: goal-hijack and forbidden-action checks

02 Track

Wraps the rest of the pipeline, capturing reasoning and writing a tamper-evident trail.

  • ReasoningCaptureMiddleware: chain-of-thought capture
  • StructuredLogger and AgentAuditor
  • LogIndexer writing to the Postgres audit_log_index
  • VaultClient: HMAC-signed receipts via Vault Transit

03 Contain

An isolated sandbox is provisioned up-front, before the decision is made.

  • ContainerProvisioner.provision_sandbox(): created, not started
  • seccomp and AppArmor syscall restriction
  • gVisor (runsc) micro-VM isolation
  • Read-only rootfs, no network by default, resource limits
  • Dynamic secret injection, revoked on teardown

04 Decide

A layered, fail-closed gateway makes the final call. Denied actions are never executed.

  • Tier 1: RuleFilter (fast deny rules)
  • Tier 1.5: ASTSemanticVerifier (code intent vs AST drift)
  • Tier 2: PiiRedactor (strip PII, fail-closed)
  • Tier 3: SemanticEvaluator (LLM risk scoring)
  • Tier 3.5: HITL gate (human approval for medium risk)

Contain-first execution

The sandbox container is provisioned in CONTAIN before DECIDE runs. If the gateway approves, the workload runs inside that already-isolated container. If it denies, or escalates to a human, the container is destroyed without the workload ever executing.

flow: IDENTIFY -> TRACK -> CONTAIN(provision) -> DECIDE
approved? execute in sandbox
denied? kill un-executed

Pipeline event trace

The audit events emitted as a single approved action moves through the pipeline.

Phase Event Status
IDENTIFY pipeline_started OK
IDENTIFY identify_passed OK
CONTAIN container_provisioned SANDBOXED
DECIDE decision_approved ALLOWED
CONTAIN container_executed EXECUTED
CONTAIN pipeline_completed DONE
