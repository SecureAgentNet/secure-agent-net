The SecureAgentNet toolkit

The security primitives behind the ITCD pipeline: a single authenticated gateway, mandate-bound intent verification, MCP tool-poisoning vetting, containerized isolation, dynamic PII redaction, and a tamper-evident audit ledger.

Intent verification

Every agent is commissioned with a mandate: the goal it was actually tasked to do. In the DECIDE phase each action is checked against that mandate, so an agent hijacked into a different objective is blocked even when its credentials are valid. No mandate, no action. The gateway is fail-closed.

Measured: 6/6 goal hijacks blocked, falling to 3/6 with mandates ablated
$ san agent commission payroll-bot --goal "Pay employee salaries"
[DECIDE] transfer_funds -> unlisted account
[DECIDE] deviates from commissioned goal
[BLOCKED] goal hijacking detected

MCP tool vetting

Before an agent trusts an MCP server, SecureAgentNet scans every tool description for injected instructions (tool poisoning), pins a content hash to catch silent rug-pulls, and scopes each tool to the agent’s mandate.

$ san mcp vet weather.json
search_docs [MALICIOUS]
hidden instruction in description

MCP gateway

The single authenticated entry point for agent traffic. Every request is identified and capability-checked before it is allowed into the ITCD pipeline.

$ san agent list
[IDENTIFY] verifying signed identity
[IDENTIFY] capabilities checked
[SUCCESS] request admitted to pipeline

PII redaction

Sensitive data is scrubbed in the DECIDE phase before any payload is evaluated or executed.

# input: "User ID 12903-X"
redact(payload) -> "[REDACTED]"

Kernel isolation

Untrusted payloads run under seccomp, AppArmor and gVisor: a read-only, no-network sandbox.

seccomp + read-only rootfs
network: none

Tamper-evident auditing

Every event is HMAC-signed with HashiCorp Vault's Transit engine and written to an append-only audit trail, so the record of what an agent did is verifiable after the fact.
