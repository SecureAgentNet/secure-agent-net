Mandate enforcement

Agents only do what they were hired to do

Commission an agent with a mandate: the goal it's sanctioned to pursue. Every action is then judged against that mandate, so a hijacked agent is blocked even when its credentials are flawless. No mandate, no action. The gateway fails closed.

How intent verification works
san evaluate
$ san evaluate transfer_funds --agent payroll-bot --intent "Pay June salary to Alice"
ALLOWED risk 0.00, serves commissioned goal
$ san evaluate transfer_funds --agent payroll-bot --intent "Divert payroll to external account"
DENIED risk 1.00, goal hijacking detected

MCP tool vetting

Poisoned tools never reach your agents

Before an agent trusts an MCP server, SecureAgentNet scans every tool description for injected instructions, pins a content hash to catch silent rug-pulls, and scopes each tool to the agent's mandate.

Kernel-hardened sandbox

Contained before it's judged

Every action is provisioned into an ephemeral container with seccomp-bpf, AppArmor, a read-only rootfs and no network by default, before the decision is even made. A denied action's sandbox is torn down without ever executing.

Tamper-evident audit

Evidence that can't be edited

The agent's reasoning is captured as it happens and every event is HMAC-signed through HashiCorp Vault. Each decision is reconstructable, each receipt independently verifiable.
